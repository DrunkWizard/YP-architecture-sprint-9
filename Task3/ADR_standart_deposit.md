### <a name="_qmphm5d6rvi3"></a>**Решение**
- Изоляция АБС: Ключевое ограничение — запрет на прямую синхронную нагрузку на АБС. Это привело к выбору асинхронной коммуникации через брокер сообщений.

- Безопасность: Требование шифрования трафика выполняется обязательным использованием TLS на всех взаимодействиях.

- Технологический стек: Выбор .NET 5+ для новых сервисов обусловлен наличием экспертизы в банке и простотой интеграции с существующим интернет-банком (ASP.NET).

- Эволюция архитектуры: Решение разбить функциональность на несколько сервисов (Каталог, Заявки, Уведомления) — это первый шаг к переходу от монолита интернет-банка к микросервисной архитектуре, но в контролируемых рамках MVP.

### <a name="_bjrr7veeh80c"></a>**Альтернативы**
Прямая синхронная интеграция с АБС через API

Почему не выбрано: Прямое обращение к API АБС создает пиковую нагрузку на ее перегруженную БД Oracle, что нарушает нефункциональное требование №3 и представляет высокий риск для стабильности всей банковской системы. Это решение неприемлемо.



**Недостатки, ограничения, риски**

Подробно опишите здесь недостатки, ограничения и риски выбранного решения.
- Eventuall consistency - использование брокера и асинхронного взаимодействия предполагает что данные какое-то время могут находиться в неконсистентном состоянии - нужно учитывать это при проектировании.
- Техдолг и легаси - использование устаревших технологий .net framework, миграции может оказаться трудоемкой
- Вендор лок. Использование Oracle и Mssql 
- Зависимость от подрядчика
